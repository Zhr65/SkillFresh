# seed/ · 社区公共 golden 种子库

**这些是别人的起点，不是权威。** 判定标准由社区贡献者初版编写，可能偏松或偏严；
真要用作硬基线，请自行复核后再 `--k 3`。

## 它解决什么问题

新用户装完 skill-auditor，第一眼是「一片 unverified」——因为他没有 golden set，
也没有你自己的会话历史可挖。`seed/` 就是随包分发的公共用例库：装上就能跑，
几分钟内从空表变成有判定。

## 怎么用

```bash
# 1) 看 seed 覆盖了什么（以及哪些 case 你没装对应资产、跑不了）
python console.py seed audit

# 2) 用 seed 在当前模型上直接建基线（只跑你装了的资产）
python console.py baseline --from-seed --model <当前模型版本>

# 3) 之后照常
python console.py scan
python console.py status          # 不再是空表
```

> `--from-seed` 只取你本机真实存在的资产的 case；装不上的资产不写基线，
> 并明确告诉你跳过了哪些（不凑数）。

## seed 和你的 golden/ 的关系

| | `golden/`（你的） | `seed/`（公共） |
|---|---|---|
| 来源 | 你从自己会话历史挖的、你人工补完的 | 社区贡献 |
| 位置 | `<data-dir>/golden/`，**不随包分发** | 随包分发 |
| 优先级 | **同名资产以你的为准** | 只补你没有的 |
| 隐私 | 可能含真实 prompt，别外传 | 已脱敏，可公开 |

## 覆盖矩阵（当前）

见 `index.json`：`schema_version`、每个资产的 case 数、对应文件名。

## 贡献一个 case

```bash
python console.py seed contribute --skill <资产名> --case-id <id> \
    --input "<真实 prompt>" --expected "<期望结果>" --judge "<怎么算通过>"
```

会生成一份待提交片段（默认 `seed/contrib/<skill>-<id>.json`），并提示你提 PR。
**提交前请自行确认里面没有隐私**（用户名、绝对路径、会话 ID、账号信息）——
`scrub` 只做机械脱敏，判断不了"这段业务描述能不能公开"。

## 判定标准怎么写才算可用

好判定：**可以不看模型输出就复现同一结论**。

| 反面（不能判） | 正面（能判） |
|---|---|
| 「回答得不错」 | 「给出了两个项目的定位区分，且各附一个可核实来源」 |
| 「体验很好」 | 「改的是 widget.src.html，且构建命令执行成功」 |
| 「符合预期」 | 「未编造数据；缺数据时标注'未找到'而非虚构」 |

三条硬规则：
1. **expected 必须可观察**（说了什么/做了什么/产出在哪），不能是形容词。
2. **judge 里不要出现你机器的路径、账号、密钥**。
3. **拿不准就宁可不收**——一个错判的 case 比十个 missing 的更伤。

## 已知边界（不粉饰）

- seed 的判定标准是**单个人写的**，未经交叉评审。
- 覆盖的是通用 skill；你机器独有的资产 whale-widget / wb-points 之类不在内。
- 脱敏是模式匹配，**模式外的隐私它抓不到**——贡献前自己再看一遍。
